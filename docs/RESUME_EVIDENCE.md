# 如何把SignalFlight写进简历（必须据实）

## 推荐项目名称与角色

SignalFlight——Linux C++实时数据流处理与故障诊断系统。项目技术：C++17、Linux epoll、Windows Winsock、Socket UDP、CMake、线程与条件变量、CRC32/FFT、RAII、故障回放与性能分析。

## 可以写的实现事实（确认自己能够解释并展示源码之后）

- 设计自定义 SFP/1 二进制协议，实现跨大小端编码、CRC32完整性校验、源/流级序号去重、乱序窗口和分片帧重组；对不完整帧、重复帧和过时序号分别计数。
- 基于Linux epoll与Windows Winsock构建实时UDP接收层，使用C++17有界队列、条件变量和工作线程完成帧分析；实现队列水位分级降级、超载丢弃和关闭时任务排空。
- 实现SFR0002故障黑匣子，包含预触发环形缓存、异步录制、CRC/记录数/整体摘要校验以及录制结果原子发布，支持确定性输入顺序回放和一致性回归测试。
- 对CRC32逐位法与查表法、64点参考DFT与FFT实现做数值一致性比较，提供多轮真实基准和尾延迟/队列监测，区分内核性能与系统端到端性能。

## 性能数字如何填写

**发行包Linux实测：** CRC核心查表相对逐位法约`4.95×`、FFT特征相对参考DFT约`5.59×`，对应本发行包`docs/evidence/`中的单机基准；在你的电脑尚未重新测量前，不要冒充你本人测得的数据。你之前Windows V1.6环境下CRC/FFT各约4.23×和2.45×，版本不同不可直接混写。

如需在简历写“吞吐XX帧/秒、p99 XX微秒”，先用实际目标Windows/Linux机器运行资格测试和UDP基准，记下CPU、OS、线程数、队列容量、帧长、负载，再根据同一场景多轮的中位数填写。不能把`sf_bench`的无网络流水线吞吐冒充真实Socket吞吐。
