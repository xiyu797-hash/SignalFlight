# 简历答辩：从代码到工程取舍

> 以下是可用于面试展示的**技术设计与实际代码位置**。每一个性能数字必须引用你本人运行的报告，不要把作者身份或生产部署经历写成自己没有做过的事实。

1. **为什么不是普通WebServer？** 目标是实时信号帧处理和异常归因，而不是HTTP请求响应。`src/pipeline.cpp`把序号重排、超时、任务过载作为业务约束。
2. **UDP为什么可能丢包？** 发送方未发、接收端内核缓冲溢出、CRC错误、应用策略丢弃都可能造成缺失。`missing_final`只表示超过容忍窗口的序号缺口。
3. **epoll和select有什么区别？** Linux epoll是内核事件通知，Windows Winsock使用select；单个UDP socket不应虚构百万并发，见`apps/sf_engine.cpp`。
4. **为什么队列有上界？** 生产速率超过消费速率时队列无界会耗尽内存；代码里通过`BoundedQueue`和水位状态机控制接入，见`include/sf/pipeline.hpp`。
5. **如何避免线程池关闭时丢任务？** 关闭接入后`tasks_.stop()`唤醒等待的消费者，队列未空时消费者继续`pop`，主线程再`join()`，见`src/engine.cpp`。
6. **并发关闭录制器有什么竞态？** 旧实现第二个`finish()`可提前返回；用`std::call_once`让全部调用等待同一次写盘完成，见`src/recorder.cpp`和`tests/test_hardening.cpp`。
7. **怎样避免把坏的录制文件当成正确结果？** SFR0002每记录CRC，文件尾部记录数和摘要，回放先验证全文件，然后生成输出，见`src/recorder.cpp`和`apps/sf_replay.cpp`。
8. **为何不能完全确定性重放并发Bug？** 输入时序相同不保证线程交错一致；测试需要同步工具或可控制的调度器。当前设计只承诺输入/逻辑时间回放。
9. **CRC优化为何安全？** 查表与逐位CRC在相同随机数据和标准测试向量上相等；基准脚本保存原始测量，不把核加速外推为系统提升。
10. **FFT到底计算多少采样？** 当前完整DSP对每个帧前64个复数采样计算频谱中心；不是1024点FFT，频谱结果来自全帧前64点，见`src/analysis.cpp`。
11. **如何解释p99？** 最近至多16384个样本的精确窗口分位数，同时保留历史桶上界；粗桶上界不可当精确数值。
12. **怎么证明项目不是仅复制教程？** 展示自己完成的真实系统测试和故障复现：多源数据、文件截断拒绝、并发finish、异常停止、弱网、过载、CRC/FFT数值与基准A/B，并提交代码修改历史和复现实验脚本。

推荐演示顺序：`-Mode fault`故障注入→`sf_replay`回放→`-Mode overload`过载→`-Mode benchmark`展示报告→`-Mode qualify`重复启停资格测试。时间允许再拿实际perf火焰图分析瓶颈。
